# Personal 에이전트 설정

> 초기 에이전트 분리 단계의 개발 기록입니다. 아래 미지원 기능·시험 개수는 당시 기준입니다.
> 현재 팀 실행·역할 프롬프트·메모리 지원 범위는 [최신 안내](../README.ko.md)를 참고하세요.

## 적용 범위

PC별 러너 데몬을 추가하거나 에이전트마다 상주 프로세스를 설치하지 않는다.
하나의 Electron 메인 프로세스가 선택한 에이전트의 기존 API/Codex 어댑터를 호출한다.
동시에 한 요청만 실행하며, 설정 추가 자체는 모델 실행기를 시작하지 않는다.
Codex 실행기는 필요할 때 시작하고 에이전트 전환 시 기존 실행기를 종료한다.

현재 구현은 텍스트 대화 실행 경로다. 조직용 Python 작업 실행 엔진을 이 경로로
통합한 것은 아니다. 중앙 작업 큐, 파일/명령 실행, 역할 프롬프트, 도구 권한 설정,
자동 도구 호출, 병렬 실행은 이번 변경으로 활성화하지 않았다.
Aegis는 여전히 Enterprise 전용이다.

## 사용 흐름

1. 상단 에이전트 선택기 옆 추가 버튼으로 설정을 만든다. 최대 20개다.
2. 모델 연결 화면에서 이름, API 공급자/키/모델 또는 ChatGPT 연결/모델을 저장한다.
3. 작업 공간에서 요청하면 현재 에이전트에 설정된 모델로 전송한다.
4. 다른 에이전트로 전환하면 해당 에이전트의 메모리 내 대화가 복원된다.

에이전트 추가 시 기존 API 키, Slack 인증, 작업 폴더를 복사하지 않는다.
설정 저장/재실행만으로 유료 모델 요청을 하지 않는다.
진행 중인 요청 또는 로그인이 있으면 에이전트 전환을 거부한다.
현재 선택과 다른 agentId를 담은 대화 요청도 메인 프로세스에서 거부한다.
모델 설정 변경은 해당 에이전트의 대화를 초기화한다. 다른 에이전트에는 영향이 없다.
대화는 앱 실행 중에만 유지되며 재실행 후 복원되는 것은 설정이다.

## 저장 권위와 호환성

- `<userData>/agent-ops-personal/agents.json`: 에이전트 ID/이름/선택의 유일한 권위.
- 기본 에이전트: 기존 `personal.json`, `codex-home` 경로를 그대로 사용한다.
- 추가 에이전트: `agents/<UUID>/personal.json`이 모델/키/연결 설정의 유일한 권위다.
- API/Slack 키는 기존 OS safeStorage 방식으로 암호화한다. 목록과 renderer에는 키를 보내지 않는다.
- Codex는 해당 에이전트 디렉터리의 `codex-home`을 사용하며 인증은 기존 공식 keyring 경로를 사용한다.
- 화면의 공급자/모델/키 등록 여부는 선택된 PersonalService에서 매번 파생한다.
  키 등록 표시는 인증 성공을 뜻하지 않는다.
- 과거 설정을 복사하는 일괄 마이그레이션은 없다. 기본 에이전트가 원래 위치를 사용하므로
  기존 API 키나 Codex 인증 위치를 이동하지 않는다.
- UUID만 디렉터리 이름으로 사용하고 경로 순회와 링크 경로를 거부한다.
- 손상된 목록을 발견하면 기존 파일을 덮어쓰지 않고 초기화를 중단한다.

## 검증 및 남은 작업

- Node 71개 테스트 통과: 에이전트별 모델/키 분리, 기존 설정 호환성,
  요청 중 변경 거부, 잘못된 ID/목록 거부, 대화 그룹 격리 포함.
- 네이티브 Electron 에이전트 시나리오 12개 검증 통과.
- 기존 Personal 16개, 공급자 8개, Codex UI 7개 회귀 항목 통과.
- 390/780/1440 창 크기 캡처와 가로 넘침 검사 통과.
- API 요청 검증은 로컬 모의 서버다. 실제 유료 공급자 호출은 하지 않았다.
- 실제 서로 다른 ChatGPT 계정의 로그인/추론과 keyring 격리는 사용자 인증이 필요해 미검증이다.
- 엔터프라이즈와 공통 작업 엔진 추출, 작업 결과 영속화, 에이전트 삭제/인증 정리,
  역할/도구 승인 정책, 배포용 설치 파일 재빌드는 남아 있다.
- 메모리 사용량은 이번 작업에서 측정하지 않았다.
