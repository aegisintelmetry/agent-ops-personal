# 서명 전 검증

자동 시험과 실제 사용자 환경 검증을 구분합니다. 체크섬은 무결성 비교값이며
발행자 서명이나 독립적인 빌드 증명이 아닙니다.

## 로컬 자동 시험

- `npm test`: 모델 경계, 오류, 취소, 팀 실패·재시도, 설정 격리, 버전·설치 정책 계약.
- `python -m unittest discover -s tests/desktop`: 로컬 코어 회귀.
- `npm run build` 및 `npm run test:desktop`: 한국어·영어, 창 크기·배율, 모델 연결, 팀 UI.
- `npm audit --audit-level=high`: npm 의존성 검사. 전체 의존성의 무취약성을 보장하지 않음.
- `BTK_DESKTOP_TEST_EXE`를 후보 패키지 실행 파일로 지정하여 패키지 검사 반복.
- `tests/package-smoke.cjs --fresh-only`: 개발용 Node/Python 없는 PATH에서 새 프로필 실행.
- `tests/stdio-smoke.cjs`: 실제 테스트 자식 프로세스의 로그 파이프 종료 후 IPC 오류 전달.
- `tests/upgrade-smoke.cjs`: 아래 두 패키지에서 같은 임시 프로필을 순서대로 열어
  모델·암호화 키·트리·프롬프트·메모리·언어 보존과 자동 모델 호출 없음 확인.

```powershell
$env:BTK_DESKTOP_PREVIOUS_EXE = '<previous-package>\AEGIS Agent Ops Preview.exe'
$env:BTK_DESKTOP_TEST_EXE = '<candidate-package>\AEGIS Agent Ops Preview.exe'
node tests/upgrade-smoke.cjs
```

기본 모드는 NSIS 설치 프로그램을 실행하지 않습니다. 실제 업데이트 시험은 별도 시험 설치에만
`--install-upgrade`를 명시하고 `BTK_DESKTOP_UPGRADE_INSTALLER`와
`BTK_DESKTOP_INSTALL_TEST_ROOT`를 지정합니다. 이전·후보 실행 파일은 같은 설치 경로여야 합니다.
실제 설치 프로그램을 실행하므로 기존 앱을 종료하고 시험 설치 경로와 사용자 데이터 보존을 확인해야 합니다.
이 시험만으로 새 PC, Windows 설치 레지스트리, 바로가기, 실제 공급자 인증까지 검증되지는 않습니다.
실제 사용자 프로필은 시험에 사용하지 않습니다.

## 새 Windows PC 확인표

1. OS 버전, 설치 파일 버전·SHA256 기록. 비밀값은 기록하지 않음.
2. 개발 도구 없는 표준 사용자로 설치하고 Personal 선택. 중앙 등록을 요구하지 않아야 함.
3. 실제 계정 또는 키를 앱에 입력하고 모델 응답 확인. 사용 요금·한도 소비를 사전 확인.
4. 서로 다른 모델의 마스터·작업자 실행, 취소, 실패 후 명시적 재시도 확인.
5. 테스트용 문자열로 차단·수정·삭제·정상 후속 대화 확인. 실제 비밀값을 붙여넣지 않음.
6. 앱 종료 후 같은 제품의 새 버전 설치. 설정·저장 메모리 유지 확인.
   일반 대화와 진행 중 작업은 재실행 후 복원되지 않음.
7. Windows 앱 제거 후 앱 실행 파일·바로가기 제거와 사용자 데이터 보존 확인.
   제거는 공급자 인증 철회가 아니며 저장 설정도 남음. 시험 계정은 공급자에서 별도 철회.
8. 새 설치 및 기존 설치 모두 재시작하여 창·오류·한영 전환·화면 배율 확인.

기존 BTK 이름의 프리뷰는 앱 ID가 달라 자동 이전·제거 대상이 아닙니다.
시험 결과에는 버전, 수행 환경, 통과/실패, 실패 문구와 미수행 항목을 함께 기록합니다.

## 배포물·서명

- 후보 버전, 패키지 버전, 코어 매니페스트, 설치 파일 이름·체크섬 일치 확인.
- LICENSE, NOTICE, 제3자 고지 포함과 비밀값 미포함 확인.
- 이미 공개한 버전의 설치 파일을 다른 바이트로 조용히 교체하지 않음.
- 정식 코드 서명 인증서 또는 서비스와 발행자 명의 확인 후 서명 파이프라인 구성.
- 코어 파일 서명은 매니페스트 해시 생성보다 먼저, 앱 서명은 리소스 수정 이후에 수행.
- 앱·코어·설치/제거 프로그램 서명과 타임스탬프를 검증한 뒤 최종 체크섬 다시 생성.
- GitHub 커밋의 Verified 표시와 Windows 실행 파일 서명은 별개.
